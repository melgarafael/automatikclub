## 1. Context

Rafael is launching an educational community inside **AutomatikLabs** (existing Next.js + Supabase app at `automatiklabs/`) focused on **Automation + AI**. The mission has three layers:

1. Teach people to **think** (logic of automation/AI)
2. Enable them to **create** with creative freedom
3. Show them how to **monetize** (services or own products)

The success metric is **Kirkpatrick level 4**: real income generated by students, not hours watched.

The goal of this project is to build a **multi-agent supertime** — skills, agents, and Python workers running locally inside Claude Code — that produces, reviews, personalizes, and publishes educational content into AutomatikLabs, coordinated through the Maestri canvas using `maestri-orchestrator` + `epic-executor`.

This document captures the **Fase 0** design only: the foundational doctrine, architectural decisions, and bootstrap of the canvas. It does NOT include implementation of the wider system — that lives in subsequent phases.

## 2. Inputs to the Design

### 2.1 Pedagogical doctrine (frameworks adopted)

Classical frameworks the system commits to:
- **Backward Design** (Wiggins & McTighe) — every track starts from a measurable result
- **Bloom's Taxonomy** — calibrates cognitive depth (target: levels 5–6, Evaluate/Create)
- **Competency-Based Education (CBE)** — students advance by demonstrated capability, not time spent
- **Cognitive Load Theory** (Sweller) — caps information density per lesson
- **Kolb's Experiential Cycle** — every concept includes experience/reflection/concept/experimentation
- **Kirkpatrick** — four-level evaluation, level 4 = student income

### 2.2 Proprietary methodologies (Rafael's frameworks)

Canonized as first-class doctrine:
- **3 Camadas da Maestria** — Técnica → Lógica → Maestria (depth ladder)
- **Empresa com IA Humanizada** — 3 Pilares: Fluxo de Trabalho · Treinamento de Agentes · Emaranhamento Multi-Agente
- **7 Passos do Script de Vendas Conversacional** — sales conversation framework
- **3 Cs da Monetização** — Criar / Capturar / Entregar valor
- **Jornada de Consciência 7 Fases** — lead awareness journey

### 2.3 Student model

Two orthogonal axes:
- **6 stages of journey** (1: Primeiros Passos → 6: Expansão e Autoridade)
- **3 cognitive personas** — Zerado / Autodidata / Organizado

Combined with the 3 Maestria layers, this forms a **3D cube** that defines how content is calibrated per student.

### 2.4 Existing platform state (discovered in `automatiklabs/supabase/migrations/`)

Already implemented:
- `tracks → courses → modules → lessons` hierarchy
- `lesson_embeddings` (pgvector, HNSW index)
- `user_lesson_progress`, `user_course_progress` with auto-completion triggers
- `lesson_ratings`
- `subscription_tier` enum + tier gating per content
- RLS migrations covering all of the above

**Not yet implemented** (will be added in later phases, NOT in Fase 0):
- Formation as a tag/category over tracks
- Competencies as first-class entities
- `user_journey_history` (persona + stage tracking)
- `pedagogical_reviews` (review workflow table)
- Learner persona / journey stage in `user_profiles`

### 2.5 Repo constraint

`automatiklabs/AGENTS.md` warns: this Next.js has breaking changes vs. training data. Any code touching the Next.js side MUST first read `node_modules/next/dist/docs/`. **Fase 0 does not touch Next.js code**, so this constraint applies only to subsequent phases.

## 4. Approach Selected

**Hub-and-Spoke** (approved over Distributed Doctrine and Monolithic Charter):
- The **Charter** is the single source of pedagogical truth, versioned in git.
- The **`automatiklabs-doctrine` skill** is a thin loader that points to the Charter and lists atomic skills to be created later.
- The **sticky notes** are live projections of slices of the Charter (Doctrine Board, Curriculum Map, Production Board, Production Log).
- Mutations to the Charter require manual re-sync of skill and notes (acceptable cost given low mutation rate).

## 6. Deliverable 2 — `automatiklabs-doctrine` Skill

Path: `~/.claude/skills/automatiklabs-doctrine/`

```
automatiklabs-doctrine/
├── SKILL.md
└── references/
    ├── charter-link.md       # Absolute path to canonical Charter
    ├── frameworks-index.md   # List of atomic skills to be created in later phases
    └── usage-examples.md     # Three short invocation examples
```

**SKILL.md principles:**
- Thin: only loader, glossary, and pointers — not the full doctrine
- Always invoked before any pedagogical task (mandatory base skill)
- Lists atomic skills (`backward-design`, `bloom-calibrator`, `tres-camadas-maestria`, etc.) WITHOUT embedding them — atomic skills are created in later phases
- Description includes WHEN to use and WHEN NOT to use (Free Content Hub is excluded)

## 9. Execution Plan for Fase 0

Single wave, executed after spec approval:

1. **Light schema investigation** — read `00001_core_users.sql` to understand `user_profiles` shape (no DB changes)
2. **Create Charter** — `mkdir -p automatiklabs/docs/educational-system/`, write CHARTER.md (canonical), write mirror in `docs/superpowers/specs/`
3. **Create `automatiklabs-doctrine` skill** — `mkdir -p ~/.claude/skills/automatiklabs-doctrine/references/`, write SKILL.md + 3 reference files
4. **Initialize 4 sticky notes** — `maestri list` to confirm names, `maestri note write` for each, `maestri list` again to verify rename
5. **Single commit** on `develop` branch with all changes; **no push**
6. **Final report** to user — files created, `maestri list` output, diff, suggested next steps for Fase 1

## 10. Out of Scope for Fase 0

Explicitly excluded (deferred to later phases):

- Creating atomic skills (`backward-design`, `bloom-calibrator`, etc.)
- Schema migrations for `competencies`, `user_journey_history`, `pedagogical_reviews`
- Writing per-area epics (Fase 1)
- Loading `maestri` skill into other terminals (Fase 1)
- Creating Python workers
- Touching Next.js code
- Pushing to remote
- Configuring `epic-executor` runner
