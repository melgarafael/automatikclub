Modulo 8 · Aula 7

Mission Control na Pratica

12 min de leitura Nivel: Avancado

Voce ja sabe o que monitorar e como configurar alertas. Agora vamos ao que realmente importa: usar o dashboard para diagnosticar problemas operacionais reais. Nesta aula, voce vai aprender a investigar 4 cenarios comuns que todo operador de agentes executores enfrenta.

Cada cenario segue o mesmo fluxo: sintoma → diagnostico → solucao. Memorize esse padrao — ele vai te salvar tempo e dinheiro em producao.

Cenario 1: Pico de Tarefas

1

Volume de Tarefas Disparou

Critico

Sintoma: Black Friday, fechamento mensal ou campanha de marketing geraram um pico de tarefas. O dashboard mostra volume 3x acima do normal. Tempo de execucao esta subindo e tarefas comecam a acumular na fila.

Diagnostico

  • Verificar se o pico e legitimo (Black Friday, fechamento) ou anomalo (possivel loop, duplicacao de tarefas, ou erro no trigger).
  • Verificar a fila de tarefas de cada agente. Qual agente esta acumulando? Financeiro com cobranças? Operacional com pedidos?
  • Verificar recursos do servidor: CPU, memoria e disco. Se algum esta acima de 85%, o gargalo e infraestrutura.
  • Verificar se ha tarefas duplicadas na fila. Um trigger mal configurado pode gerar a mesma tarefa multiplas vezes.

Solucao: Se o pico e legitimo, aumente a concorrencia do agente temporariamente ou distribua tarefas entre agentes. Se ha duplicacao, corrija o trigger e limpe a fila. Para picos previstos (Black Friday), configure auto-scaling com antecedencia.

Cenario 2: Agente com Falha

2

Agente Financeiro Nao Consegue Acessar ERP

Atencao

Sintoma: O agente financeiro esta retornando erros em todas as tarefas que exigem acesso ao ERP. Relatorios nao sao gerados, cobranças nao sao processadas. Taxa de sucesso caiu para 20%.

Diagnostico

  • Verificar os logs de erro do agente financeiro. Identificar o tipo: timeout de conexao, autenticacao falha, endpoint indisponivel.
  • Verificar se o ERP esta online acessando diretamente. Se o sistema externo caiu, o problema nao e do agente.
  • Verificar se as credenciais de API do ERP estao validas. Tokens expiram, senhas sao trocadas em manutencoes programadas.
  • Verificar se houve mudanca na API do ERP (nova versao, endpoint alterado, campos obrigatorios adicionados).

Solucao: Se o ERP esta fora, ative modo de espera — armazene tarefas na fila e reprocesse quando voltar. Se credenciais expiraram, renove imediatamente. Se a API mudou, atualize a skill do agente para a nova versao.

Cenario 3: Tempo de Execucao Alto

3

Tarefas Demorando Demais para Completar

Atencao

Sintoma: O tempo medio de execucao subiu de 10s para 90s. Tarefas simples (consultar saldo, gerar alerta) estao demorando tanto quanto tarefas complexas (gerar relatorio mensal). Performance degradada em todos os agentes.

Diagnostico

  • Verificar status da API do LLM em status.openai.com. Se houver incidente ativo, a lentidao e externa.
  • Verificar o tamanho do prompt de cada agente. Prompts acima de 4000 tokens aumentam significativamente o tempo de resposta.
  • Verificar se ha chamadas a APIs externas lentas. Um sistema externo respondendo devagar trava toda a cadeia.
  • Verificar se ha tarefas executando em serie quando poderiam ser paralelas. Gargalo de concorrencia causa fila desnecessaria.

Solucao: Se a API do LLM esta lenta, aguarde. Se os prompts estao grandes, otimize — remova instrucoes redundantes. Se APIs externas estao lentas, implemente cache para dados que nao mudam frequentemente. Habilite execucao paralela onde possivel.

Cenario 4: Loop de Delegacao

4

Tarefas Pulando Entre Agentes Infinitamente

Critico

Sintoma: Os logs mostram que uma tarefa foi delegada do Financeiro para o Operacional, que delegou de volta para o Financeiro, que delegou novamente. A tarefa nunca e executada, o custo de API dispara e o cliente fica sem resposta.

Diagnostico

  • Verificar os logs de delegacao para identificar o ciclo: qual tarefa, quais agentes, quantas vezes.
  • Verificar se os gatilhos estao sobrepostos. "Fatura" ativa Financeiro e Comercial? "Pedido de compra" ativa Operacional e Financeiro?
  • Verificar se o max_delegation_depth esta configurado. Sem limite, o loop nao para.
  • Verificar se algum agente esta rejeitando tarefas que deveria executar. Um escopo mal definido faz o agente devolver a tarefa indevidamente.

Solucao: Configure max_delegation_depth: 3 imediatamente. Revise os gatilhos e elimine sobreposicoes. Defina claramente o escopo de cada agente no Agents.md. Para a tarefa presa no loop, force a execucao manual ou escale para humano.

Checklist Diario de Monitoramento

Execute esta rotina todos os dias pela manha, em menos de 5 minutos. Consistencia aqui e o que separa agentes confiaveis de agentes que "funcionam as vezes":

  • Abrir dashboard de tarefas e verificar volume processado nas ultimas 24h (2 min)
  • Checar tarefas com erro — meta: abaixo de 5/dia. Acima de 10, investigue imediatamente
  • Revisar alertas — ler resumo dos alertas que dispararam. Padroes repetidos indicam causa raiz
  • Verificar custo de API — picos inesperados indicam loop infinito ou prompt descontrolado
  • Confirmar que heartbeats estao verdes — todos os agentes online e executando

Checklist Semanal de Performance

Execute toda segunda-feira para manter a qualidade operacional ao longo do tempo:

  • Gerar relatorio de performance semanal — tarefas processadas, taxa de sucesso, tempo medio
  • Comparar com semana anterior — identificar tendencias (melhoria ou degradacao)
  • Identificar top 5 tarefas que falharam — analisar causa raiz de cada uma
  • Ajustar configuracoes — triggers, limites, timeouts baseados nos dados da semana
  • Testar todos os agentes — enviar tarefa de teste para cada um e confirmar execucao

Quando Escalar

Quando Escalar o Problema

Se o problema persiste apos o diagnostico basico descrito nos cenarios acima, nao fique tentando resolver sozinho por horas. Escale de forma inteligente: contate o suporte da OpenAI para problemas de API (rate limits, erros 500, degradacao), contate o provedor de infraestrutura para problemas de servidor (CPU, memoria, rede), ou pergunte no grupo da comunidade AutomatikLabs para problemas de configuracao e melhores praticas.

Referencia Rapida: Troubleshooting Operacional

Use esta tabela como guia rapido. Quando um sintoma aparecer no Mission Control, consulte a causa provavel e tome a acao imediata:

Sintoma Causa Provavel Acao Imediata
Taxa de sucesso abaixo de 85% Sistema externo fora ou credenciais expiradas Verificar sistemas, renovar credenciais
Tempo de execucao > 120s API do LLM lenta ou prompt muito grande Checar status.openai.com, otimizar prompt
Erros tipo 429 (rate limit) Muitas tarefas simultaneas ou loop de delegacao Implementar fila, checar logs de delegacao
Tarefas escaladas > 25% Escopo do agente mal definido ou skills faltando Revisar Agents.md, adicionar skills
Heartbeat vermelho Agente offline ou processo crashou Reiniciar agente, checar logs do servidor
Custo de API disparou Loop de delegacao ou tarefa em loop infinito Pausar agente, revisar logs, configurar max_depth
Dica

O melhor dia para resolver um problema operacional e ontem. O segundo melhor e agora. Uma tarefa financeira falhando silenciosamente pode significar cobranças nao processadas e receita perdida. Nunca deixe um alerta para depois.

Resultado

Com monitoramento diario, revisao semanal e diagnostico rapido, seus agentes executam processos em producao com confianca. Voce sabe exatamente quantas tarefas foram processadas, qual a taxa de sucesso, e tem dados concretos para otimizar. Isso e operar como profissional.
