Subagents: Delegando Tarefas

15 min de leitura Nivel: Avancado

Subagents sao agentes executores especializados que recebem tarefas do orquestrador. Pense neles como operadores de areas distintas: cada um tem sua especializacao, seus sistemas e suas regras. O orquestrador recebe a tarefa e delega para o especialista correto.

Hierarquia de Agentes

Arquitetura de Delegacao

Orquestrador (Main Agent)
delega para
💰

Agente Financeiro

Processa cobranças, gera relatorios financeiros, monitora fluxo de caixa

⚙️

Agente Operacional

Monitora estoque, processa pedidos, gera alertas de reposicao

📈

Agente Comercial

Qualifica leads, gera propostas, acompanha pipeline de vendas

Como Funciona

1

Tarefa chega ao orquestrador

Uma tarefa e recebida pelo orquestrador — pode ser via API, webhook, agendamento ou trigger externo. O orquestrador nunca executa diretamente — sua unica funcao e classificar e delegar.

2

Orquestrador classifica por area e delega

Baseado nos triggers configurados (palavras-chave, tipo de tarefa), o orquestrador decide qual agente especializado deve executar. "Cobranca vencida" vai para Financeiro. "Verificar estoque" vai para Operacional. "Novo lead" vai para Comercial.

3

Agente especializado executa e retorna resultado

O agente especializado processa a tarefa usando seus proprios processos, suas proprias skills e seus proprios sistemas. O resultado volta ao orquestrador com status de execucao (sucesso, falha, ou escalado para humano).

Configurando Subagents

Aqui esta a estrutura basica de configuracao de subagents por area operacional:

// config/subagents.json { "orchestrator": "main-agent", "subagents": [ { "name": "financeiro", "trigger": ["cobranca", "fatura", "pagamento", "relatorio financeiro", "fluxo de caixa"], "soul": "soul-financeiro.md" }, { "name": "operacional", "trigger": ["estoque", "pedido", "entrega", "reposicao", "fornecedor"], "soul": "soul-operacional.md" }, { "name": "comercial", "trigger": ["lead", "proposta", "contrato", "pipeline", "follow-up"], "soul": "soul-comercial.md" } ] }

Regras de Delegacao

Regra Descricao Exemplo
Trigger unico Cada trigger deve ativar apenas um agente executor "cobranca" ativa so Financeiro, nunca Comercial
Fallback obrigatorio Se nenhum trigger bater, a tarefa fica no orquestrador "Status geral do sistema" fica no principal
Timeout de execucao Se o agente nao completar em X segundos, escala Timeout de 60s para tarefas simples, 300s para relatorios
Escalacao Agente pode escalar tarefa para humano Transacao > R$50k precisa de aprovacao manual
Contexto da tarefa preservado Parametros, prioridade e deadline acompanham a delegacao Agente sabe a prioridade e o prazo da tarefa
Regra critica

O orquestrador NUNCA deve perder o controle. Se um agente especializado nao conseguir executar a tarefa, ela volta para o orquestrador. Sem isso, tarefas ficam presas e ninguem percebe ate o cliente reclamar.

Dica importante

Cada agente executor precisa de acesso apenas aos sistemas que precisa. Principio do menor privilegio: o agente financeiro nao precisa acessar o WMS, e o operacional nao precisa acessar o gateway de pagamento. Isso reduz riscos e erros de execucao.

Checklist da Aula

  • Hierarquia desenhada — sei quem e o orquestrador e quais sao os agentes executores por area
  • Triggers definidos — cada agente tem palavras-chave operacionais da sua area
  • Subagents configurados — arquivo de config criado com triggers por tipo de tarefa
  • Fallback testado — tarefas sem trigger definido ficam no orquestrador
