Módulo 6 — Aula 2

Credenciais de Sistemas: Variáveis de Ambiente e Secrets

20 min de leitura Nível: Intermediário

O erro #1 de quem começa

O erro mais comum — e mais perigoso — é hardcodar credenciais diretamente no código. Quando seu agente acessa ERPs, CRMs, planilhas, bancos de dados e gateways de pagamento, cada sistema tem suas credenciais. Se você sobe o código para o GitHub com essas credenciais expostas, qualquer pessoa no mundo pode acessar os sistemas do seu negócio.

⚠ Caso real

Bots automatizados varrem o GitHub 24/7 procurando API keys expostas. Em minutos, sua key pode ser usada para gerar cobranças na sua conta — casos de R$50.000+ em um fim de semana são documentados.

O que NUNCA fazer

# ❌ ERRADO — credenciais expostas no código import stripe stripe.api_key = "sk_live_abc123xyz789..." # 💀 PERIGO! DATABASE_URL = "postgresql://user:senha@host:5432/db" # 💀 PERIGO!

A solução: variáveis de ambiente

Variáveis de ambiente são valores armazenados fora do código, no sistema operacional ou em arquivos de configuração que nunca vão para o repositório.

Como funciona o arquivo .env

# Arquivo: .env (na raiz do projeto) OPENAI_API_KEY=sk-proj-abc123xyz789 STRIPE_SECRET_KEY=sk_live_abc123xyz789 GOOGLE_SHEETS_CREDENTIALS=./credentials/sheets-service-account.json DATABASE_URL=postgresql://user:senha@host:5432/meu_banco ERP_API_TOKEN=erp-token-abc123 OPENCLAW_SECRET=minha-chave-secreta

Como usar no código

# ✅ CORRETO — credenciais vêm do ambiente import os import stripe stripe.api_key = os.getenv("STRIPE_SECRET_KEY") # Conectar ao banco de dados import psycopg2 conn = psycopg2.connect(os.getenv("DATABASE_URL"))
💡 Como funciona

os.getenv("STRIPE_SECRET_KEY") lê o valor da variável de ambiente. O código nunca contém a credencial real — apenas o nome da variável que aponta para ela. Isso vale para qualquer sistema: Stripe, banco de dados, ERP, Google Sheets.

Configurando o .gitignore

O arquivo .gitignore diz ao Git quais arquivos ele deve ignorar. Seu .env precisa estar nessa lista.

# Arquivo: .gitignore .env .env.local .env.production *.key *.pem
1

Crie o .env na raiz do projeto

Adicione todas as suas variáveis sensíveis nesse arquivo, uma por linha, no formato NOME=valor.

2

Adicione .env ao .gitignore

Verifique que o .gitignore contém a linha .env. Faça isso antes do primeiro commit.

3

Crie um .env.example

Crie um arquivo .env.example com as variáveis sem os valores reais. Esse arquivo vai pro repositório como documentação.

# Arquivo: .env.example (esse VAI pro repositório) OPENAI_API_KEY=sua-key-aqui STRIPE_SECRET_KEY=sua-key-aqui GOOGLE_SHEETS_CREDENTIALS=caminho/para/credentials.json DATABASE_URL=postgresql://user:senha@host:5432/banco ERP_API_TOKEN=seu-token-aqui OPENCLAW_SECRET=sua-chave-aqui

Secrets em servidores (HostGator/VPS)

Em produção, as variáveis de ambiente são configuradas diretamente no servidor, não em arquivos.

Via SSH no servidor

# Adicionar variável permanente no servidor echo 'export OPENAI_API_KEY="sk-proj-abc123"' >> ~/.bashrc source ~/.bashrc # Verificar se está configurada echo $OPENAI_API_KEY

Checklist de segurança de APIs

  • Zero hardcoded keys — Nenhuma API key aparece diretamente no código
  • .env no .gitignore — Arquivo de variáveis nunca vai pro repositório
  • .env.example criado — Documentação de quais variáveis são necessárias
  • Spending limits configurados — Limites de gasto em todos os provedores e sistemas
  • Keys em gerenciador — Todas as credenciais salvas no 1Password
  • Histórico do Git limpo — Nenhuma key foi commitada acidentalmente no passado
⚠ Se você já commitou uma key

Revogar a key imediatamente no provedor e gerar uma nova. Não basta remover do código — o histórico do Git mantém tudo. A key antiga já está comprometida.

✓ Resultado
