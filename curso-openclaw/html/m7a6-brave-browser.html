Brave Browser: Navegação Web

15 min de leitura Nível: Iniciante

Para que serve?

O Brave Browser dá ao agente a capacidade de pesquisar dados de mercado em tempo real. Isso significa que ele pode monitorar preços da concorrência, coletar dados de fornecedores, e trazer informações atualizadas que não estão na base operacional.

🔍

Inteligência competitiva

Monitorar preços, estoque e ofertas de concorrentes

📄

Coleta de dados

Extrair informações de sites de fornecedores

🔐

Privacidade

Brave bloqueia trackers e anúncios por padrão

Por que Brave e não Chrome?

O Brave é baseado no Chromium (mesmo motor do Chrome), mas com privacidade nativa:

  • Bloqueio de trackers — Sites não rastreiam a atividade do agente
  • Sem anúncios invasivos — Páginas carregam mais limpo e rápido
  • Brave Search — Motor de busca próprio, sem viés do Google
  • Leve — Consome menos memória que o Chrome

Instalação

1

Instale o Brave no servidor

No servidor onde o OpenClaw roda, o Brave precisa estar instalado. O OpenClaw geralmente cuida disso automaticamente durante o setup. Se não, siga as instruções do painel.

2

Ative a ferramenta de navegação

No OpenClaw, vá em Ferramentas → Navegação Web e ative. Selecione Brave como navegador padrão.

3

Configure os limites

Defina: máximo de buscas por conversa (recomendado: 3-5) e domínios bloqueados (sites que o agente não deve acessar).

Como o agente navega

O agente não "abre o Brave e navega visualmente" como você faria. Ele usa a ferramenta de navegação de forma programática:

  1. Recebe a tarefa — "Qual o preço do produto X no concorrente Y?"
  2. Decide que precisa buscar — O agente percebe que não tem essa informação na base
  3. Executa a busca — Via Brave Search, busca "produto X site concorrente Y"
  4. Extrai o conteúdo — Lê os resultados e extrai a informação relevante
  5. Registra o resultado — "Produto X no concorrente Y: R$149,90 (fonte: site oficial, coletado hoje)"
💡 Quando a navegação é útil

A navegação web complementa a base operacional. Use para dados que mudam frequentemente (preços de fornecedores, estoque de concorrentes, cotações) ou que são muito amplos para manter em uma base de dados operacional.

⚠ Limitações

O agente não consegue navegar em sites que exigem login, resolver CAPTCHAs, ou interagir com JavaScript complexo. Ele funciona melhor com conteúdo público e estático.

Boas práticas

  • Limite as buscas — Cada busca consome tokens (= custo). 3-5 buscas por conversa é um bom equilíbrio
  • Bloqueie sites sensíveis — Adicione à blacklist sites de conteúdo adulto e fake news
  • Cite fontes — Configure o agente para sempre informar de onde veio a informação coletada
  • Cache quando possível — Se uma informação é buscada frequentemente, considere adicionar à base operacional ao invés de buscar toda vez
