Projeto: Criando seu 2o Agente

25 min de leitura Nivel: Avancado

Hora de colocar a mao na massa. Nesta aula, vamos criar um Agente Financeiro como subagent executor do seu agente principal. Ao final, voce tera um sistema multiagente funcionando com delegacao automatica de tarefas operacionais.

Passo 1: Criar Estrutura

Primeiro, vamos criar a estrutura de pastas para o agente financeiro:

# Navegar ate o projeto cd ~/openclaw # Criar pasta do agente financeiro mkdir -p agents/financeiro # Criar arquivos base touch agents/financeiro/soul.md touch agents/financeiro/agents.md

Passo 2: Definir Soul

O Soul do agente financeiro define sua funcao operacional e seus limites:

# agents/financeiro/soul.md Voce e o operador financeiro. ## Funcao - Processar cobranças e faturas - Gerar relatorios financeiros (diarios, semanais, mensais) - Monitorar inadimplencia e fluxo de caixa - Executar conciliacao bancaria ## Modo de Operacao - Preciso e objetivo — numeros nao mentem - Sempre inclua periodo de referencia nos relatorios - Compare com periodo anterior automaticamente - Destaque anomalias e valores fora do padrao ## Limites - NUNCA processe transacoes acima de R$50k sem aprovacao humana - NAO acesse sistemas fora da area financeira - Se a tarefa nao for financeira, devolva ao orquestrador - Se nao conseguir executar apos 3 tentativas, escale para humano

Passo 3: Definir Agents.md

O Agents.md do financeiro define processos operacionais e regras de execucao:

# agents/financeiro/agents.md ## Agente Financeiro Papel: Executar processos financeiros autonomamente Escopo: Cobranças, relatorios, fluxo de caixa, conciliacao Processos: 1. Receber tarefa do orquestrador com parametros 2. Validar se a tarefa esta dentro do escopo financeiro 3. Executar usando os sistemas autorizados (ERP, gateway) 4. Retornar resultado com status (sucesso/falha/escalado) 5. Registrar execucao nos logs Escalacao: - Transacoes > R$50k sem aprovacao → humano - Tarefas operacionais → Agente Operacional - Tarefas fora do escopo → Orquestrador

Passo 4: Criar uma Skill

Crie a skill gerar_relatorio para o agente financeiro:

// skills/gerar_relatorio.json { "name": "gerar_relatorio", "description": "Gera relatorio financeiro do periodo solicitado", "parameters": { "periodo": "string (ex: 2026-05)", "tipo": "vendas | despesas | fluxo_caixa | inadimplencia", "formato": "pdf | csv | json" }, "systems": ["erp", "banco_dados_financeiro"] }

Passo 5: Registrar no Orquestrador

Registre o agente financeiro com seus triggers operacionais:

// config/triggers.json { "financeiro": { "keywords": [ "cobranca", "fatura", "pagamento", "relatorio financeiro", "fluxo de caixa", "inadimplencia", "conciliacao", "receita", "despesa", "saldo" ], "priority": 1, "fallback": "main-agent" } }

Passo 6: Testar Delegacao

Envie estas tarefas de teste e confira se cada uma vai para o agente correto:

1

Teste: "gerar relatorio de vendas do mes"

Esperado: deve ir para o Agente Financeiro. Contem "relatorio" e "vendas" — gatilhos financeiros.

2

Teste: "verificar estoque do produto X"

Esperado: deve ir para o Agente Operacional. Contem "estoque" e "produto" — gatilhos operacionais.

3

Teste: "qual o status da tarefa #123?"

Esperado: deve ficar no Orquestrador. Nenhum gatilho especifico ativado — tarefa generica de status.

Validacao

Se os 3 testes passaram, seu sistema multiagente operacional esta funcionando! O orquestrador classifica corretamente e delega para o agente executor certo baseado no tipo de tarefa.

Passo 7: Verificar Logs de Execucao

Confirme que as execucoes estao registradas nos logs:

# Ver logs do agente financeiro npm run logs --agent=financeiro # Saida esperada: [2026-05-25 10:32:15] TASK_RECEIVED orchestrator → financeiro [2026-05-25 10:32:15] TASK: {type: "gerar_relatorio", periodo: "2026-05"} [2026-05-25 10:32:18] EXECUTING: consultando ERP... [2026-05-25 10:32:22] COMPLETED: relatorio gerado com sucesso [2026-05-25 10:32:22] RESULT: {status: "success", output: "relatorio_vendas_2026-05.pdf"}

Checklist da Aula

  • Estrutura criada — pasta agents/financeiro com soul.md e agents.md
  • Soul definido — funcao operacional, modo de operacao e limites do agente financeiro
  • Agents.md escrito — processos de execucao e regras de escalacao
  • Skill criada — gerar_relatorio configurado com parametros
  • Triggers configurados — palavras-chave financeiras no config/triggers.json
  • 3 testes passando — financeiro, operacional e orquestrador corretos
  • Logs verificados — execucoes de tarefas aparecendo com status correto
