Módulo 7 — Aula 4

Integração com GitHub

18 min de leitura Nível: Intermediário

Por que GitHub para agentes?

O GitHub não é só para programadores. Para quem cria agentes, ele serve como sistema de versionamento e backup automático das configurações do agente.

💾

Backup de configs

System prompts e configurações versionados com histórico

🔃

Rollback fácil

Voltou ao prompt anterior em segundos se algo quebrar

👥

Auditoria

Rastrear quem mudou qual processo e quando

Criando o repositório

1

Crie uma conta no GitHub

Se ainda não tem, crie em github.com. O plano gratuito é suficiente — repositórios privados são grátis.

2

Crie um repositório privado

Clique em "New Repository". Nome sugerido: meu-agente-openclaw. Marque como Private — suas configurações não devem ser públicas.

3

Organize a estrutura

Crie a seguinte estrutura de pastas no repositório:

# Estrutura recomendada do repositório meu-agente-openclaw/ prompts/ system-prompt.txt # Prompt principal workflow-cobranca.txt # Workflow de cobrança workflow-relatorio.txt # Workflow de relatório configs/ openclaw-settings.json # Configurações exportadas integrations.md # Lista de integrações ativas knowledge/ processos.md # SOPs do agente catalogo-operacional.md # Catálogo de operações .gitignore # Arquivos a ignorar README.md # Documentação do agente

Automação de backup

A cada vez que você alterar um prompt ou configuração, basta commitar e push para o GitHub. Isso cria um registro permanente de cada mudança.

# Salvar alteração no GitHub git add . git commit -m "atualiza workflow de cobrança: adiciona regra de horário" git push
💡 Mensagens de commit

Escreva mensagens descritivas: "atualiza workflow de cobrança: ajusta prazo de vencimento" é muito melhor que "atualização". Isso facilita encontrar quando e por que algo mudou.

Restaurando versão anterior

Se uma mudança no prompt quebrou o agente, você pode voltar à versão anterior com um clique:

1

Acesse o histórico

No GitHub, abra o arquivo do prompt e clique em "History". Você verá cada versão com data e descrição.

2

Compare versões

Clique em qualquer commit para ver exatamente o que mudou — linhas adicionadas em verde, removidas em vermelho.

3

Restaure

Copie o conteúdo da versão que funcionava e cole de volta no OpenClaw. Commit a restauração com mensagem clara: "reverte prompt para versão de 20/05".

⚠ Lembrete de segurança

O .gitignore deve incluir .env e quaisquer arquivos com credenciais. Nunca faça commit de API keys, tokens, ou senhas — mesmo em repositório privado.

✓ Resultado

Seu agente agora tem backup versionado no GitHub. Qualquer mudança é rastreável e reversível. Na próxima aula, vamos conectar canais de comando: onde o agente reporta resultados e recebe tarefas.
