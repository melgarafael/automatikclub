Configurando Usuarios e Permissoes

10 min de leituraNivel: Intermediario

Nem todo mundo deve poder delegar as mesmas tarefas ao seu agente. O dono precisa de controle total, enquanto um membro da equipe so pode solicitar tarefas basicas. Configurar niveis de delegacao desde o inicio evita execucoes indevidas e custos descontrolados.

Tipos de Usuario

TipoPode DelegarNao PodeExemplo
DonoTodas as tarefas + configurar—Dono do negocio
GerenteDelegar tarefas + ver relatoriosAlterar configs do agenteGerente de area
EquipeSolicitar tarefas basicas + ver proprios dadosExecutar processos criticosMembro da equipe
SistemaExecucao automatica via crons/triggersAcoes manuaisCron job, webhook

Template de Configuracao

O arquivo users.json na pasta config/ define as permissoes:

{ "roles": { "owner": { "permissions": ["delegate", "execute", "approve", "monitor", "configure"], "rate_limit": null }, "manager": { "permissions": ["delegate", "execute", "monitor"], "rate_limit": "50/hour" }, "team": { "permissions": ["delegate_basic", "view_own"], "rate_limit": "20/hour" }, "system": { "permissions": ["execute_scheduled", "trigger"], "rate_limit": "100/hour" } } }

Aplicando Configuracao

Apos editar o arquivo, aplique as mudancas:

npm run apply-config
Atencao

Rate limits protegem sua API key e controlam o custo de execucoes. Sem eles, um unico usuario ou trigger pode gerar centenas de execucoes desnecessarias. Configure sempre, mesmo em projetos pequenos.

Dica

Comece restritivo e va liberando conforme necessario. E muito mais facil conceder permissao de delegacao do que revogar — especialmente quando alguem ja se acostumou a delegar certas tarefas.

Checklist da Aula

  • Tipos de usuario definidos — dono, gerente, equipe, sistema
  • Permissoes configuradas — cada role com suas acoes de delegacao
  • Rate limits aplicados — controle de execucoes por hora ativo
  • Config testada — apply-config sem erros
