Organizando seu Workspace

10 min de leituraNivel: Iniciante

Organizacao desde o inicio evita dor de cabeca quando o agente ganha mais processos. Um workspace bem estruturado e a diferenca entre escalar operacoes com tranquilidade e perder horas procurando arquivos de configuracao.

Estrutura Ideal

meu-agente/ ├── 📁 soul/ │ └── soul.md ← Papel operacional ├── 📁 agents/ │ ├── agents.md ← Processos e regras │ └── prompts/ │ ├── relatorio.md ← Template de relatorios │ └── alerta.md ← Template de alertas ├── 📁 config/ │ ├── users.json ← Permissoes de delegacao │ ├── settings.json ← Configuracoes gerais │ └── channels.json ← Canais operacionais ├── 📁 skills/ │ ├── financeiro/ ← Skills de processos financeiros │ ├── estoque/ ← Skills de controle de estoque │ └── relatorios/ ← Skills de geracao de relatorios ├── 📁 memory/ │ ├── short-term/ ← Contexto da tarefa atual │ └── long-term/ ← Padroes operacionais aprendidos ├── 📁 integrations/ │ ├── telegram/ ← Canal de comandos/resultados │ ├── database/ ← Conexoes com bancos de dados │ └── api/ ← APIs externas (ERPs, CRMs, etc) ├── 📁 logs/ │ └── (logs de execucao automaticos) ├── .env └── package.json

Diagrama de Execucao

Veja como os dados fluem durante a execucao de um processo:

Comando
→
Soul
→
Processos
→
Skills
→
Sistemas

O Comando chega pelo canal operacional. A Soul define o papel. Os Processos aplicam as regras. As Skills executam as acoes. Os Sistemas conectados recebem e entregam dados.

Dica

Crie a estrutura agora, mesmo que muitas pastas fiquem vazias. Voce vai agradecer depois quando precisar adicionar uma nova skill operacional ou conectar um novo sistema e ja tiver o lugar certo para colocar.

Checklist da Aula

  • Estrutura de pastas criada — todas as pastas no lugar
  • Convencoes seguidas — kebab-case, SCREAMING_SNAKE
  • Diagrama entendido — fluxo Comando → Soul → Processos → Skills → Sistemas
