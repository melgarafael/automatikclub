Testando e Iterando Seu Prompt

18 min de leitura Nivel: Intermediario

Voce escreveu o prompt operacional. Tem papel, contexto, processos, criterios de sucesso, tratamento de excecoes e guardrails. Mas como saber se os processos realmente executam corretamente? A resposta e simples: testando cada processo sistematicamente.

Nenhum prompt fica perfeito na primeira versao. O segredo dos melhores engenheiros de agentes e que eles testam cada processo, medem o resultado e ajustam — e repetem esse ciclo ate 90%+ dos processos executarem corretamente.

O Processo de Iteracao

1

Monte sua lista de processos para testar

Liste todos os processos que seu agente deve executar. Para cada um, defina o resultado esperado com metricas claras. Essa lista e seu benchmark operacional — voce vai usa-la toda vez que mudar o prompt.

2

Execute todos os processos

Dispare cada processo e registre o resultado real. Nao pule nenhum — voce precisa ver a operacao completa. Compare cada output com o resultado esperado.

3

Identifique as falhas

Para cada processo que falhou, identifique por que falhou. Faltou contexto operacional? Processo mal definido? Exemplo ausente? Guardrail fraco? Saber o "por que" e mais importante que saber o "o que".

4

Ajuste e re-teste

Faca um ajuste por vez. Se voce mudar 5 processos de uma vez, nao vai saber qual mudanca resolveu (ou criou) o problema. Apos cada ajuste, rode todos os testes novamente — inclusive os que ja estavam passando.

Regra de Ouro

Faca um ajuste por vez e re-teste tudo. Mudar varias coisas simultaneamente e a forma mais rapida de criar novos problemas enquanto tenta resolver os antigos.

Log de Testes — Modelo Preenchido

Aqui esta um exemplo real de como documentar seus testes de processos. Use esta tabela como modelo:

Processo Resultado Esperado Resultado Real Status Ajuste
Gerar relatorio diario Relatorio com 5 KPIs as 8h Gerou corretamente com todos os KPIs Passou —
Cobrar inadimplente dia 5 Enviar msg com valor e link Enviou sem link de pagamento Falhou Adicionar template de cobranca com link obrigatorio
Confirmar consulta 24h antes Msg personalizada via Telegram Confirmou corretamente Passou —
Gerar pedido estoque baixo Pedido ao fornecedor Y Pedido gerado para fornecedor errado Falhou Corrigir mapeamento fornecedor-produto no contexto
Reagendar no-show Oferecer 3 horarios alternativos Ofereceu horarios ja ocupados Falhou Verificar disponibilidade antes de oferecer
Escalar cobranca > R$5k Pedir aprovacao gerente Escalou corretamente Passou —
Processar com dados inconsistentes Parar e alertar admin Processou com dados errados Falhou Adicionar validacao pre-execucao

Neste exemplo, 3 de 8 processos passaram completamente (37%). Precisamos chegar a pelo menos 90% antes de colocar o agente em producao.

O Que Testar

Use esta checklist para garantir cobertura completa nos seus testes de processos:

  • Geracao de relatorios — todos os KPIs presentes, formato correto, horario de entrega
  • Cobranca e pagamentos — valor correto, link de pagamento, cronograma de escalacao
  • Confirmacao de agenda — mensagem personalizada, horario correto, canal correto
  • Pedidos automaticos — fornecedor correto, quantidade certa, preco validado
  • Escalacao para humano — escala no momento certo com relatorio completo
  • Tratamento de excecoes — para quando deve parar, notifica quando deve notificar
  • Limites financeiros — respeita tetos, pede aprovacao acima do limite
  • Validacao de dados — detecta dados inconsistentes e para antes de processar
  • Notificacoes e alertas — dispara no threshold correto, para as pessoas certas
  • Fallback quando processo falha — comportamento correto apos 2-3 tentativas

Quando Seus Processos Estao Prontos

Criterio de Aprovacao

Seu agente esta pronto para producao quando 90% ou mais dos processos executam corretamente. Isso significa que em 10 processos testados, pelo menos 9 geram o resultado esperado. Os 10% restantes devem ser cenarios raros cobertos por escalacao para humano.

Exemplo Completo de Ciclo de Iteracao

Vamos ver um ciclo real de melhoria, do inicio ao fim:

v1

Versao 1 — Prompt Basico

Prompt: "Voce gerencia a operacao de uma clinica. Cuide da agenda e dos relatorios."
Resultado: 2/10 processos passaram. Relatorios vagos, cobrancas sem dados, pedidos errados.
Diagnostico: Faltam todos os 5 blocos operacionais. Precisa reconstruir.

v2

Versao 2 — Com Papel e Contexto Operacional

Ajuste: Adicionou cargo "gerente de operacoes", equipe, horarios, regras operacionais.
Resultado: 4/10 passaram. Dados corretos agora, mas processos mal definidos — agente improvisa os passos.
Diagnostico: Falta bloco de processos detalhados.

v3

Versao 3 — Com Processos e Exemplos

Ajuste: Adicionou 5 processos detalhados com triggers e passos, 3 exemplos de execucao.
Resultado: 7/10 passaram. Muito melhor! Mas agente processou cobranca de R$ 8.000 sem aprovacao.
Diagnostico: Faltam guardrails operacionais.

v4

Versao 4 — Com Guardrails Operacionais

Ajuste: Adicionou limites financeiros, escalacao, anti-erro em cascata.
Resultado: 9/10 passaram. Unico ponto fraco: gerou pedido para fornecedor errado.
Diagnostico: Mapeamento fornecedor-produto incompleto no contexto.

v5

Versao 5 — Ajuste Final

Ajuste: Completou mapeamento de fornecedores + adicionou validacao pre-pedido.
Resultado: 10/10 passaram. Pronto para producao!

Nunca Pare de Testar

Mesmo depois de ativar, continue monitorando os processos do agente. Novos cenarios vao aparecer — situacoes que voce nao previu, dados que chegam em formato inesperado. Atualize o prompt conforme novos padroes surgem. Um bom prompt operacional e um documento vivo.

Ferramentas para Testar

Proprio OpenClaw Testar processos direto na plataforma Ja incluso
Modo sandbox Executar processos sem efeitos reais (sem enviar msgs, sem cobrar) Gratis
Colegas como testadores Criam cenarios inesperados que testam os guardrails Gratis
