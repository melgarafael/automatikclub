# M2 — Ativacao: Seu OpenClaw no Ar em 30 Minutos

> Modulo pratico de instalacao. O aluno sai com um agente executor de IA rodando no proprio servidor, conectado ao ChatGPT, acessivel de qualquer lugar e sabendo resolver os problemas mais comuns.

---

## M2A1 — Contratando sua VPS na HostGator

**Conceito-chave:** A HostGator oferece um plano VPS especifico para OpenClaw que ja vem com o ambiente pre-configurado — sem necessidade de setup manual.

**O que o aluno faz:** Contrata a VPS OpenClaw na HostGator, paga, aguarda ativacao e salva as credenciais de acesso (IP, senha root, porta SSH).

**Conteudo principal:**
- A VPS e um servidor dedicado onde o agente roda 24/7 sem concorrer com outros sites
- Nao confundir com hospedagem compartilhada (Plano P, M, Turbo) — essas nao funcionam para OpenClaw pois nao permitem processos em background
- O pagamento com cartao de credito libera acesso mais rapido (minutos vs 1-2 dias no boleto)
- O email de ativacao contem IP, senha root e porta SSH — guardar em local seguro
- O sistema operacional deve ser Linux (Ubuntu 22.04+), nunca Windows Server

**Erros comuns:**
- Contratar hospedagem compartilhada em vez de VPS
- Selecionar Windows Server em vez de Linux Ubuntu
- Perder o email de ativacao com as credenciais

**Dica pratica:** Salve IP, senha root e porta SSH em um gerenciador de senhas — essas informacoes sao usadas em todas as aulas seguintes.

**Aula anterior:** -- (primeira do modulo) | **Proxima:** M2A2

## M2A2 — Ativando o OpenClaw na VPS

**Conceito-chave:** A VPS HostGator ja vem com OpenClaw pre-instalado, mas o aluno tambem aprende o fluxo manual (clone, install, setup) para entender o que roda por baixo.

**O que o aluno faz:** Conecta via SSH, verifica que o OpenClaw esta rodando, acessa o painel web na porta 3000 e aprende o fluxo de instalacao manual (git clone, npm install, cp .env, npm run setup).

**Conteudo principal:**
- Conectar via SSH usando `ssh root@SEU_IP_AQUI` (Terminal no Mac/Linux, PowerShell ou PuTTY no Windows)
- Verificar status com `openclaw status` — o servico deve estar ativo
- Acessar o painel web em `http://SEU_IP:3000`
- Fluxo manual: `git clone` > `cd openclaw` > `npm install` > `cp .env.example .env` > `npm run setup`
- Validar instalacao com `npm run status` — todos os checks (Node.js, Database, Config, Dependencies) devem mostrar OK

**Erros comuns:**
- Nao ter o PuTTY instalado no Windows e o comando ssh nao funcionar
- O `npm install` travar por conflitos de versao (resolver com `--legacy-peer-deps`)
- Rodar tudo como root em producao (criar usuario dedicado depois, na aula 5)

**Dica pratica:** Se o npm install travar, rode `npm install --legacy-peer-deps` para resolver conflitos de versao entre pacotes.

**Aula anterior:** M2A1 | **Proxima:** M2A3

## M2A3 — Conectando ao ChatGPT

**Conceito-chave:** O OpenClaw usa a assinatura do ChatGPT Plus (US$ 20/mes fixo) em vez da API por consumo — muito mais barato para agentes que executam processos o dia inteiro.

**O que o aluno faz:** Vincula sua conta ChatGPT Plus ao OpenClaw pelo painel (Configuracoes > LLM), escolhe o modelo e valida a conexao com `openclaw test-llm`.

**Conteudo principal:**
- ChatGPT Plus (custo fixo US$ 20/mes) vs API por consumo (escala rapido, pode passar de US$ 100/mes)
- Fluxo: Painel OpenClaw > Configuracoes > LLM > Selecionar "ChatGPT Plus" > Login com email/senha OpenAI
- Modelos disponiveis: gpt-4o-mini (rapido/barato, recomendado para comecar), gpt-4o (para escalar), gpt-4-turbo (casos complexos)
- Testar conexao via painel ou `openclaw test-llm` — deve retornar "Connection successful"
- A assinatura Plus precisa estar ativa; se vencer, o agente para de funcionar

**Erros comuns:**
- Tentar usar API por consumo em vez de ChatGPT Plus
- Assinatura Plus vencida ou cancelada sem perceber
- Escolher modelo muito pesado (gpt-4-turbo) quando gpt-4o-mini resolve

**Dica pratica:** Comece com gpt-4o-mini — e o mais rapido e barato. Suba para gpt-4o so quando precisar de mais qualidade em tarefas complexas.

**Aula anterior:** M2A2 | **Proxima:** M2A4

## M2A4 — Seu Primeiro Teste

**Conceito-chave:** O aluno delega tarefas ao agente via API (curl POST) e recebe resultados em JSON — nao e um chat, e um executor autonomo.

**O que o aluno faz:** Inicia o agente com `npm run start`, envia tarefas via curl na porta 3000, analisa os campos da resposta JSON e testa 3 tipos de tarefa (analise, geracao, processamento complexo).

**Conteudo principal:**
- Iniciar agente: `cd /root/openclaw && npm run start` (escuta na porta 3000)
- Enviar tarefa: `curl -X POST http://localhost:3000/api/task -H "Content-Type: application/json" -d '{"task": "..."}'`
- Resposta JSON tem: status, task, result, model, execution_ms, tokens_used
- 3 cenarios de teste: analise de dados (uso de disco), geracao de conteudo (relatorio JSON), processamento complexo (diagnostico multi-passo)
- Tabela de troubleshooting rapido: timeout (agente parado), 401 (ChatGPT desconectado), ECONNREFUSED (porta errada), resultado vazio (modelo nao configurado)

**Erros comuns:**
- Esquecer de deixar o terminal com `npm run start` aberto enquanto testa em outra janela
- Enviar tarefa muito ambigua e receber resultado vazio
- Nao perceber que o agente ainda nao tem acesso aos sistemas do negocio (isso vem no Modulo 3)

**Dica pratica:** Tempo de execucao abaixo de 3000ms e considerado bom. Se estiver consistentemente acima de 10s, considere upgrade da VPS.

**Aula anterior:** M2A3 | **Proxima:** M2A5

## M2A5 — Liberando Acesso Total

**Conceito-chave:** Para o agente operar processos reais — APIs externas, webhooks, bancos remotos — voce precisa liberar acesso de rede, configurar dominio e criar usuario dedicado por seguranca.

**O que o aluno faz:** Configura firewall (UFW), libera portas (22, 80, 443, 3000), configura dominio com DNS tipo A, instala SSL com Let's Encrypt, cria usuario dedicado `openclaw` e testa acesso remoto.

**Conteudo principal:**
- Firewall UFW: habilitar, liberar SSH (22) primeiro, depois portas 80, 443 e 3000
- Dominio: criar registro DNS tipo A apontando para o IP da VPS (propagacao de 5min a 48h)
- SSL: instalar Certbot + plugin Nginx, gerar certificado com `sudo certbot --nginx -d agente.seudominio.com.br`
- Usuario dedicado: criar usuario `openclaw`, mover projeto, ajustar permissoes — nunca rodar como root em producao
- Teste final: enviar tarefa remotamente do computador pessoal via curl

**Erros comuns:**
- Ativar o firewall antes de liberar a porta SSH 22 (perde acesso ao servidor)
- Expor porta do admin sem autenticacao configurada
- Nao criar usuario dedicado e continuar rodando tudo como root

**Dica pratica:** Use dominio proprio (agente.suaempresa.com.br/api/task) em vez de IP direto — facilita integracao com outros sistemas e passa mais profissionalismo.

**Aula anterior:** M2A4 | **Proxima:** M2A6

## M2A6 — Troubleshooting: Os 5 Erros Mais Comuns

**Conceito-chave:** Esta aula e um guia de referencia para consultar quando algo der errado — cobre os 5 erros mais frequentes da instalacao com diagnostico e solucao passo a passo.

**O que o aluno faz:** Salva a pagina nos favoritos, conhece os 5 erros mais comuns e aprende a rodar o script de diagnostico universal que verifica tudo de uma vez.

**Conteudo principal:**
- **ECONNREFUSED** — servico nao esta rodando: verificar processos, reiniciar agente, checar se porta 3000 esta livre
- **401 Unauthorized** — ChatGPT Plus desconectado: verificar assinatura ativa, reconectar credenciais no painel, testar com `openclaw test-llm`
- **ENOMEM (heap out of memory)** — VPS sem RAM: criar swap de 2GB (`fallocate`), aumentar limite Node.js com `NODE_OPTIONS="--max-old-space-size=1024"`, considerar upgrade para 4GB
- **ETIMEDOUT** — firewall ou DNS bloqueando: testar conectividade (`ping google.com`), configurar DNS Google (8.8.8.8), permitir conexoes de saida no UFW
- **Module not found** — dependencias faltando: rodar `rm -rf node_modules && npm install`, usar `--legacy-peer-deps`, verificar Node.js v18+
- Script de diagnostico universal: verifica SO, memoria, disco, Node, npm, porta 3000, conectividade OpenAI e .env em 8 checks

**Erros comuns:**
- Nao verificar requisitos minimos da VPS (2GB RAM, Ubuntu 22.04+, 10GB disco livre)
- Tentar resolver problemas sem rodar o script de diagnostico primeiro
- Nao compartilhar a saida do diagnostico quando pedir ajuda no grupo

**Dica pratica:** Salve o script de diagnostico no servidor como arquivo (`diagnostico.sh`) para rodar rapidamente sempre que precisar — com a saida dele, qualquer problema pode ser resolvido pelo suporte.
