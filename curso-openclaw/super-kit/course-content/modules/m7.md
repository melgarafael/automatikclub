# M7 — Integracoes: Conectando aos Sistemas do Negocio

Integracoes sao o que transformam o agente de uma IA isolada em um executor autonomo conectado ao ecossistema real do negocio. Neste modulo, o aluno conecta Notion (SOPs e processos), Google Workspace (email, agenda e planilhas), GitHub (backup versionado), canais de comando (WhatsApp, Discord, Slack), e Brave Browser (pesquisa de mercado). Ao final, o agente le, escreve, reporta e pesquisa em sistemas reais.

---

## M7A1 — Visao Geral das Integracoes

**Conceito-chave:** Integracoes sao os bracos do agente — sem elas, ele so pensa; com elas, ele executa processos reais no ecossistema do negocio.

**O que o aluno faz:** Mapeia as integracoes disponiveis, entende o que cada uma faz, e define qual ativar primeiro com base no seu caso de uso.

**Conteudo principal:**
- Mapa visual do ecossistema: Gestao (Notion, Google, GitHub), Operacional (ERPs, gateways de pagamento, canais de comando), Navegacao (Brave Browser, web search, web scraping)
- Tabela de compatibilidade com 8 integracoes: Notion, Gmail, Calendar, Drive, GitHub, Stripe/Gateway, Brave, Slack — mostrando leitura, escrita, tempo real e dificuldade
- Guia de priorizacao por tipo de agente: Financeiro (Stripe + Gmail + Planilhas), Operacional (Calendar + Notion + Gmail), Inteligencia (Brave + Drive + Notion), Monitoramento (GitHub + Slack + Brave)
- Toda integracao segue o padrao: Autenticacao → Configuracao → Mapeamento → Teste
- Regra pratica: comece com UMA integracao, teste bem, so depois adicione outra

**Erros comuns:**
- Tentar ativar todas as integracoes de uma vez (cada peca movel aumenta chance de quebra)
- Nao testar a integracao antes de colocar em producao
- Dar permissoes excessivas (acesso total quando so precisa de leitura)

**Dica pratica:** Comece com a integracao que resolve o problema mais doloroso do negocio. Para a maioria dos casos, Notion (SOPs) ou Gmail (cobranças) sao as melhores primeiras escolhas.

## M7A2 — Integracao com Notion

**Conceito-chave:** O Notion funciona como central de SOPs e processos — o agente consulta procedimentos antes de executar e registra resultados apos executar.

**O que o aluno faz:** Cria uma Integration no Notion, gera o token, compartilha paginas com a integracao, configura no OpenClaw, e testa leitura/escrita.

**Conteudo principal:**
- Notion serve 3 funcoes para o agente: Central de SOPs (consultar procedimentos), Controle operacional (registrar execucoes), Registro de processos (documentar acoes automaticamente)
- Passo a passo em 5 etapas: criar Integration em notion.so/my-integrations, copiar token ntn_, compartilhar paginas com a integracao, configurar no OpenClaw, testar conexao
- Principio do menor privilegio: agente consultor (so leitura), agente executor (leitura + escrita de resultados), agente de logs (so escrita)
- O agente le databases com filtros (ex: buscar workflows com status "Pendente") e escreve criando paginas/linhas/atualizando propriedades

**Erros comuns:**
- Criar o token mas esquecer de compartilhar as paginas (agente retorna "not found" em tudo)
- Dar acesso a todo o workspace em vez de apenas as paginas necessarias
- Nao organizar o Notion para facilitar a consulta do agente (dados bagunçados = respostas ruins)

**Dica pratica:** Crie um workspace separado no Notion so para o agente — isso isola os dados operacionais dos pessoais e facilita o gerenciamento de permissoes.

## M7A3 — Google Workspace: Gmail, Calendar e Drive

**Conceito-chave:** O Google Workspace da ao agente capacidade de enviar cobranças por email, agendar execucoes de processos e acessar planilhas de controle financeiro.

**O que o aluno faz:** Conecta Gmail, Calendar e Drive via OAuth 2.0, define permissoes por servico, cria calendario dedicado para o agente, e testa cada integracao.

**Conteudo principal:**
- Gmail: enviar cobranças, alertas operacionais e relatorios por email. Comece com somente leitura, habilite envio so apos testes extensivos
- Calendar: agendar execucoes recorrentes de processos. Criar calendario dedicado "execucoes programadas" com janelas de execucao e buffer entre processos
- Drive: acessar planilhas de controle e gerar relatorios. Nunca dar acesso ao Drive inteiro — restringir a pasta especifica ("Agente — Operacional")
- OAuth 2.0 explicado como analogia: "e como dar uma chave especifica para o agente que so abre as portas que voce escolheu"
- 3 niveis de permissao visual: Seguro (so leitura), Moderado (leitura + criar eventos + responder emails), Avancado (acesso total — so para agentes muito testados)

**Erros comuns:**
- Habilitar envio de email sem testes extensivos (pode gerar problemas legais com cobranças mal formatadas)
- Dar acesso ao Drive inteiro em vez de pasta especifica
- Nao configurar horarios de execucao (agente executando cobranças as 3h da manha)

**Dica pratica:** Configure regras de agendamento com horario comercial (8h-18h) e buffer entre processos para evitar sobrecarga — isso previne que o agente execute cobranças em horarios inapropriados.

## M7A4 — Integracao com GitHub

**Conceito-chave:** O GitHub serve como sistema de versionamento e backup automatico das configuracoes do agente — cada mudanca em prompts, workflows e configs fica rastreavel e reversivel.

**O que o aluno faz:** Cria repositorio privado no GitHub, organiza a estrutura de pastas (prompts, configs, knowledge), configura backup e aprende a restaurar versoes anteriores.

**Conteudo principal:**
- GitHub para agentes serve 3 funcoes: Backup de configs (prompts e configuracoes versionados), Rollback facil (volta ao prompt anterior em segundos se algo quebrar), Auditoria (rastrear quem mudou qual processo e quando)
- Estrutura de repositorio recomendada: prompts/ (system-prompt, workflows), configs/ (settings, integracoes), knowledge/ (SOPs, catalogo operacional), .gitignore, README.md
- Backup via git add + commit + push com mensagens descritivas (nao "atualizacao")
- Restaurar versao anterior: History no GitHub → Compare versoes → Copiar versao que funcionava → Commit a restauracao

**Erros comuns:**
- Mensagens de commit genericas como "atualizacao" (impossivel saber o que mudou)
- Commitar API keys ou tokens (mesmo em repo privado, e inseguro)
- Nao usar .gitignore para excluir .env e credenciais

**Dica pratica:** Escreva mensagens de commit descritivas como "atualiza workflow de cobranca: ajusta prazo de vencimento" — isso transforma o historico do Git em um log operacional util.

## M7A5 — Canais de Comando: WhatsApp, Discord e Slack

**Conceito-chave:** Canais de comando sao a interface de comunicacao operacional — onde o agente reporta resultados de processos executados e recebe tarefas do operador.

**O que o aluno faz:** Entende as diferencas entre WhatsApp, Discord e Slack, escolhe o canal adequado para seu caso de uso, e configura pelo menos um canal de comando.

**Conteudo principal:**
- Tabela comparativa detalhada: WhatsApp (alertas rapidos, pago, janela 24h para respostas livres), Discord (central de operacoes do time, gratuito, canais + threads), Slack (notificacoes operacionais estruturadas, freemium, blocos e botoes)
- WhatsApp: numero dedicado para o agente, mensagem de status operacional, regra de 24h + templates pre-aprovados
- Discord: bot via Developer Portal, restringir a canais especificos (#comandos-agente), evitar ativar em todos os canais
- Slack: app com scopes minimos (chat:write, channels:read, channels:history, app_mentions:read)
- Diferenca pratica: WhatsApp = comandos rapidos, Discord = central de operacoes, Slack = notificacoes estruturadas

**Erros comuns:**
- Ativar o bot do Discord em todos os canais (gera ruido e confusao)
- Nao entender a regra de 24h do WhatsApp (fora da janela, so templates pre-aprovados)
- Usar canal pessoal em vez de dedicado para o agente

**Dica pratica:** Para a maioria dos casos, Discord e a melhor opcao inicial — gratuito, facil de configurar, e o sistema de canais + threads permite separar processos por tipo naturalmente.

## M7A6 — Brave Browser: Navegacao Web

**Conceito-chave:** O Brave Browser da ao agente a capacidade de pesquisar dados de mercado em tempo real — monitorar precos, coletar dados de fornecedores e buscar informacoes que nao estao na base operacional.

**O que o aluno faz:** Instala/ativa o Brave no OpenClaw, configura limites de busca e dominios bloqueados, e testa pesquisas de mercado com o agente.

**Conteudo principal:**
- 3 capacidades principais: inteligencia competitiva (monitorar precos e ofertas de concorrentes), coleta de dados (extrair info de sites de fornecedores), privacidade (Brave bloqueia trackers e ads por padrao)
- Por que Brave e nao Chrome: bloqueio de trackers nativo, sem anuncios, Brave Search proprio, menor consumo de memoria
- Fluxo de navegacao: agente recebe tarefa → percebe que nao tem o dado → executa busca via Brave Search → extrai conteudo → registra resultado com fonte e data
- Configurar limites: maximo 3-5 buscas por conversa, dominios bloqueados, citacao de fontes obrigatoria
- Limitacoes reais: nao funciona com sites que exigem login, CAPTCHAs, ou JavaScript complexo

**Erros comuns:**
- Nao limitar buscas por conversa (custo de tokens explode)
- Esperar que o agente navegue como humano (ele lida com conteudo publico e estatico)
- Buscar sempre na web em vez de manter dados frequentes na base operacional

**Dica pratica:** Se uma informacao e buscada frequentemente (ex: preco de um fornecedor), adicione-a a base operacional com um cron de atualizacao — isso e mais barato e confiavel do que buscar toda vez.
